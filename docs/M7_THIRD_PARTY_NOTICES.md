## 5. The authoritative inventory for any given release

This document deliberately does **not** enumerate the full transitive
dependency tree: it changes with every lockfile update, and a stale
hand-written list would be worse than none. For the artifact being
released, the authoritative inventory is generated by the release
workflow itself and uploaded with the artifact under
`build/audit-release/`:

- `rust-license-inventory.md` — every resolved Cargo package with its
  declared license expression, generated by
  `scripts/generate-rust-license-inventory.py` from `cargo metadata`.
  The script fails if any third-party package lacks declared license
  metadata. (M0 audit baseline: 45 Cargo packages, 44 third-party, all
  with declared expressions — re-verify per release, do not reuse that
  count as current evidence.)
- `rust-runtime-dependency-tree.txt` and
  `android-release-dependency-tree.txt` — resolved runtime trees.
- `android-license-report/` — the dependency-license-report output,
  now covering `releaseRuntimeClasspath` as well as debug.

Release-gate rule: before any install is called a release, the
reviewer must open the release run's own inventory, confirm no
`MISSING THIRD-PARTY LICENSE` entry, confirm every packaged
third-party notice that a license requires is present, and confirm
any media/codec or patent-sensitive format dependency with
appropriate review. An inventory from an older run is not evidence
for a newer artifact.

## 6. What is NOT in this inventory

- No font files are added to this repository by this workstream and
  no font license is newly asserted for Android.
- No Adobe or Effekseer code, parser, or license is included: `.aep`
  is proprietary with no licensed parser in this project and `.efkproj`
  has no parser/converter here. Their absence is a support limit (see
  `docs/M7_SUPPORT_MATRIX.md`), not a licensing gap to paper over.
- Test-only dependencies (`org.json:json:20250517` for JVM tests,
  `junit:junit:4.13.2`) are not shipped and are listed here only so a
  reviewer does not mistake a test dependency for a runtime one.
